## 1. Cosa è stato fatto

### Registro del montaggio e stato derivato
- **`_montaggio.json`**, scritto da `src/production.write_montage()` insieme al file
  finale (produzione e rimontaggio): nome e formato del file, data, durata, sha256 del
  copione montato, segmenti e scelte dei take usati, musiche (nome e sha256), offset e
  durata della voce, sezioni (intro, parlato, outro) in secondi nel file finale.
- Non è uno stato: descrive il file. Lo stato dell'episodio si **deriva** confrontandolo
  con la run di adesso (`src/episode_info.py`): `pronto`, `da_aggiornare` con i `motivi`
  (`copione`, `take`, `musiche`), `in_corso` (dal lock), `non_prodotto`.
- `turn_at.py` prende l'offset della voce da `_montaggio.json`: `musiche_usate.json` resta
  da un mix precedente anche quando l'episodio viene rimontato senza musiche (prima
  questo spostava i tempi). Le run vecchie usano ancora `musiche_usate.json`.

### Schermo "Episodio"
- **`tools/episode_info.py --run-dir R`**: titolo, stato, formato, durata, voci (ruolo,
  nome pronunciato), data di montaggio, file finale (percorso relativo), sezioni,
  trascrizione con `inizio_finale`/`fine_finale` per battuta (nel file finale, intro
  compresa), elenco dei file della run (senza nascosti, lock e `_lavoro.json`, con
  `interno` per i file di lavoro).
- **`tools/waveform.py --run-dir R --points N`** (`src/waveform.py`): picchi 0–1 sul
  file finale, decodificato con ffmpeg (mono, 2 kHz, con timeout), in cache in
  `_forma_onda_N.json` legata allo sha256 del file.

### Montaggio
- **G7**: il nome del file finale è il titolo di `episodio.json` per le run nuove
  (`final_basename`). Una volta montato resta quello anche se il titolo cambia; le run
  già montate con il titolo del copione tengono il loro nome.
- **G1**: `mix.py` rimonta dalla cache anche senza musiche (prima era un errore), zero
  sintesi, sotto il lock di lavoro (operazione `montaggio`). La logica è
  `src/production.assemble_episode()`, condivisa con la produzione. Segmenti mancanti →
  `SegmentsMissing` con l'elenco.

### Retake
- **D1** (`src/retake.py`): `--direction` (ripetibile) solo dalla whitelist
  `retake.indicazioni` di `config.yaml` (default nel codice per i config vecchi). Le tag
  vanno solo nel testo inviato per i take nuovi; la chiave del segmento resta quella del
  testo approvato, quindi copione e approvazione non cambiano. Errori:
  `UnknownDirection`, `DirectionNeedsTextEdit` ("Pronuncia diversa"),
  `ConflictingDirections` (opposte), `TooManyTakes` (`retake.max_takes`, 3). La stima
  conta le tag. Le indicazioni restano nei metadati del take
  (`segmenti/take_info.json`).
- **G5**: `retake.py --list N` restituisce ogni take (originale compreso) con etichetta
  del wireframe, scelta, indicazioni e anteprima in contesto (battuta prima, take, battuta
  dopo), montata dalla cache senza sintesi; `--with-music` aggiunge il sottofondo.
- Generazione e scelta tengono il lock di lavoro; una voce con il consenso revocato non
  si usa per un retake (`ConsentRequired`). Percorsi `preview_ui` relativi; `cost_eur`.
- Anteprime scritte in modo atomico con nome unico (`atomic_output`).

## 3. Decisioni prese in questa fase

- **"Altre indicazioni, con parole tue"** (campo libero del wireframe) **non è
  supportato**: in D1 nessun testo libero arriva al sintetizzatore fuori dal copione
  approvato. Il contratto dice all'adattatore di non passarlo.
- **Tag delle indicazioni** (`[lentamente]`, `[rapidamente]`, `[entusiasta]`, `[calmo]`,
  `[serio]`, `[sorride]`, `[con pause]`): punti di partenza da tarare a orecchio, in
  `config.yaml`. Vanno davanti al testo della battuta.
- **Etichette dei take** come nel wireframe: il take 1 è "Take originale", il take K è
  "Take K-1".
- **`_montaggio.json`** come descrizione del file finale, da cui si deriva lo stato (non è
  un campo di stato).
- Un episodio con take generati ma **non scelti** resta `pronto`: cambia solo quando
  cambia la scelta.
