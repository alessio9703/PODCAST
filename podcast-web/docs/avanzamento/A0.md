# A0 · Piano del controller web (podcast-web)

> 2026-10-08. Specifica: `podcast-agent/docs/CONTRATTO_INTERFACCIA.md` (tag `v1.0-web`).
> Stato: **approvato il 2026-10-09**, con le decisioni in fondo (§16).

## 1. Architettura in breve

```
browser ──HTTPS──▶ CMS LIFE (login) ──HTTPS + header firmati──▶ VPS: uvicorn (1 processo)
                                                                  ├─ app/ingresso   chi è l'utente (demo | cms)
                                                                  ├─ app/api        rotte HTTP + SSE
                                                                  ├─ app/servizi    permessi, gettoni, esiti, avvio
                                                                  ├─ app/agente     UNICO punto che lancia tools/*.py
                                                                  ├─ app/lavori     coda a 1 worker, eventi
                                                                  ├─ app/file       caricamenti e download
                                                                  ├─ registro.py    registro attività JSONL
                                                                  └─ config.py      tutto da variabili d'ambiente
                                                                        │ sottoprocesso (lista, mai shell)
                                                                        ▼
                                                                  podcast-agent/.venv/bin/python tools/<x>.py
```

- `podcast-web` non importa niente da `podcast-agent` e non lo modifica. Legge solo, dal
  disco: l'esistenza di `output/<run>/` (come `runs_list.py`), `output/<run>/_eventi.jsonl`
  (avanzamento), i file da scaricare (solo quelli che l'agente elenca) e il file `VERSION`
  (§7). Scrive solo i caricamenti
  nelle tre librerie (regole del contratto, "Caricamenti").
- Lo stato degli episodi non sta nel controller: ogni vista si chiede all'agente
  (`runs_list`, `run_status`, `script_show.in_corso`). In memoria restano solo la coda dei
  lavori e i gettoni di conferma; un riavvio li perde senza perdere dati (la UI ripiega su
  `run_status`).

## 2. Tabella dei comandi (`app/agente/tabella.py`)

Una voce per **azione** (non per tool: lo stesso tool con usi diversi ha voci diverse, così
argomenti, timeout e permesso sono stretti). Ciò che non è in tabella non parte.

Per ogni voce: `tool`, argomenti ammessi con il loro tipo, `timeout` (s, dal contratto
"Processi, tempi e coda"; `None` = nessun timeout duro), `lungo` (va in coda), `permesso`,
`conferme` (error_type di esito 3 → flag che si aggiunge **solo** con un gettone valido),
`fase`.

Tipi di argomento, tutti controllati dall'esecutore prima di lanciare:
`run` (nome di run: `^[A-Za-z0-9][A-Za-z0-9._-]{0,150}$` e cartella reale, non link, sotto
`output/`), `nome` (documento/voce/brano: niente `/ \ ..`, niente controllo, niente `.` o
`-` iniziali, ≤ 200), `testo` (libero, ≤ limite per campo, niente NUL), `int` (con
intervallo), `scelta` (elenco chiuso), `flag`, `by` (**solo** dall'ingresso), ripetibili.

processo, ambiente **minimo** costruito da zero: `PODCAST_AGENT_WEB=1`, `PATH` (fisso +

per intero a fine processo (limite di dimensione), stderr solo nel log del server (troncato).
Timeout → SIGTERM, dopo 10 s SIGKILL → 504.

## 3. Esiti verso il browser (`app/servizi/esiti.py`)

Un solo formato JSON per ogni risposta API:

```json
{"ok": true,  "dati": { … JSON dell'agente ripulito … }}
{"ok": false, "esito": "correggibile|servizio_esterno|decisione|timeout|controller",
 "error_type": "VersionConflict", "messaggio": "testo leggibile", "details": { … },
 "riprovabile": false, "gettone": "…solo per esito 3…", "scade_il": "…solo per esito 3…"}
```

| Esito dell'agente | HTTP | Note |
|---|---|---|
| exit 0 | 200 (202 per un lavoro messo in coda) | `dati` ripulito |
| exit 1, stato concorrente: `RunBusy`, `VersionConflict`, `LockTimeout`, `ApprovalRequired` | 409 | `riprovabile` vero per `RunBusy`, `LockTimeout`, `Model{RateLimited,Overloaded,Unreachable}` |
| exit 1, il resto | 422 | `details` com'è (serve alla UI per evidenziare il campo) |
| exit 1, errori dell'adattatore: `InvalidArguments`, `NotAllowedInWebMode`, `ByRequired`, e `InternalError` | **500** (proposta, §16) | solo nel log; al browser `messaggio` generico, niente `details` |
| exit 2 | 502 | "servizio esterno", mai `riprovabile` |
| exit 3 | 409 | `gettone` legato a utente, azione, run e domanda |
| timeout | 504 | `error_type: "Timeout"` |
| JSON assente o non valido | 500 | log |

`error_type` dell'agente: sempre e solo quelli di §3 del contratto; un nome fuori elenco si
tratta come l'errore generico del suo exit code. Gli errori **del controller** (che non
vengono dall'agente) hanno `esito: "controller"` e un piccolo elenco chiuso, distinto per
forma (in italiano): `NonAutenticato` 401, `NonPermesso` 403, `NonTrovato` 404,
`RichiestaNonValida` 400, `FileNonAmmesso` 415, `FileTroppoGrande` 413, `FileEsistente`
409 (con gettone per sostituire), `GettoneNonValido` 409, `Timeout` 504, `CodaPiena` 503.

**Pulizia del JSON**: via le chiavi con percorsi del server elencate in §1 del contratto
(`run_dir`, `session_file`, `script_file`, `episodio_file`, `musiche_file`,
`musiche_usate_file`, `output`, `path`, `percorso`, `voices_dir`, `music_dir`,
`timings_file`, `segnali_file`, `voci_usate`, `text_file`, `audio_file`, `events_file`,
`file_ui`, `preview*`), più `voice_id`, `cache_reason`, `pid`; poi una rete di sicurezza su
**ogni** stringa: un valore che contiene la cartella dell'agente, la home o un percorso
assoluto viene tolto e registrato nel log. I file da scaricare tornano come URL del
controller (`/api/episodi/<run>/file/<nome>`), mai come percorsi.

**Gettoni di conferma** (`app/servizi/gettoni.py`): `secrets.token_urlsafe(32)`, in memoria
(un solo processo), validi `GETTONE_DURATA_S` (default 300 s), **monouso**. Il record lega:
utente, azione, run, `error_type`, impronta di `details`, e gli argomenti originali della
richiesta. Conferma: `POST /api/conferme/<gettone>` (eventuale `{"scelta": …}` per
`LessonRemovalRequired`) → il controller rilancia **gli argomenti salvati** + il flag che la
tabella associa a quell'`error_type`; il browser non può cambiare niente. Un gettone di un
altro utente, scaduto, già usato o di un'altra run → 409 `GettoneNonValido`. Per gli esiti 3
senza flag (`AmbiguousName`, `ConsentRequired`, `RecordingChanged`, `RevokedMeanwhile`) il
gettone c'è comunque (formato uniforme), ma la risposta è una nuova richiesta normale (il
nome esatto scelto, il consenso con lo sha256/revisione nuovi).

## 4. Ingresso e firma (`app/ingresso/`)

Un'unica funzione `utente_della_richiesta(request) -> Utente(id, nome, ruoli)`; nessun altro
modulo legge header di identità.

**`AUTH_MODE=demo`**: utente fisso da `DEMO_UTENTE`, `DEMO_NOME`, ruoli = tutti. Il server
parte solo se `HOST` è `127.0.0.1`; in più ogni richiesta con un indirizzo client non di
loopback → 401 (difesa se qualcuno lancia uvicorn a mano su `0.0.0.0`).

**`AUTH_MODE=cms`**: header (nomi in un solo punto, `app/ingresso/cms.py`):

| Header | Contenuto |
|---|---|
| `X-LIL-Utente` | id stabile dell'utente nel CMS, `^[A-Za-z0-9._@-]{1,100}$` |
| `X-LIL-Nome` | nome da mostrare e da usare per `--by`, UTF-8 **percent-encoded** (gli header sono latin-1), ≤ 100 caratteri decodificato |
| `X-LIL-Ruoli` | ruoli separati da virgola, senza spazi (`autore,approvatore`) |
| `X-LIL-Timestamp` | secondi Unix (intero) |
| `X-LIL-Firma` | `v1=<hex>` di HMAC-SHA256(`LIL_SEGRETO`, stringa canonica) |

Stringa canonica (righe separate da `\n`, UTF-8):

```
v1
<timestamp>
<METODO in maiuscolo>
<percorso come ricevuto, con la query: /api/episodi?gruppo=bozze>
<utente>
<ruoli, come nell'header>
<nome, come nell'header (percent-encoded)>
```

Verifica: tutti gli header presenti, `|ora − timestamp| ≤ 60 s`, confronto con
`hmac.compare_digest`; altrimenti **401 con corpo fisso** `{"ok": false, "esito":
"controller", "error_type": "NonAutenticato"}`, nessun dettaglio (il motivo va solo nel log
del server). Ruoli sconosciuti ignorati. `--by` = nome dell'ingresso (se vuoto, l'id).
Segreto: `LIL_SEGRETO` (≥ 32 byte), opzionale `LIL_SEGRETO_PRECEDENTE` per la rotazione.
La specifica completa per il dev, con un esempio calcolato e il codice di riferimento in
Python, va in `DEPLOY.md` (A4); il "CMS finto" di A4 usa lo stesso codice.

**CSRF**: le richieste che cambiano qualcosa vogliono `Content-Type: application/json` (o
`application/octet-stream` per i caricamenti) e l'header `X-LIL-Richiesta: 1`, che un form di
un altro sito non può mandare. La sessione e il login sono del CMS.

## 6. Registro attività (`registro.py`)

`REGISTRO_FILE` (JSONL), aperto in append con `O_APPEND`, una riga per scrittura sotto lock
di thread, `fsync`, permessi 0600, mai riscritto. Campi: `at` (UTC ISO), `utente`, `nome`,
`azione`, `run`, `esito` (`ok` / `error_type`), `exit_code`, `http`, `costo_stimato_usd` /
`costo_stimato_eur` se ci sono, `lavoro` (id), `dettagli` (piccoli e senza percorsi: versione
approvata, voce, numero di battuta…). Si registrano **tutte** le azioni che cambiano qualcosa
(obbligatorie: approvazioni e ritiri, consensi e revoche, conferme con gettone, produzioni,
retake, stesure e revisioni, caricamenti e sostituzioni) e i rifiuti per permesso. Per una
produzione il controller lancia `estimate.py` subito prima di metterla in coda e registra
`cost_usd`/`cost_eur`: il costo non arriva mai dal browser. Le letture non si registrano.

## 7. Avvio, versione dell'agente, /salute

All'avvio (`python -m app`, anche da systemd), prima di aprire la porta:
1. configurazione valida (`AGENT_DIR`, `AGENT_PYTHON` dentro `AGENT_DIR/.venv`, segreto in
   modalità cms, `HOST=127.0.0.1` in demo);
2. `doctor.py --web` con l'esecutore: exit 0 e `web_mode` ok, altrimenti uscita con codice ≠ 0
   e motivo nel log;
3. **versione dell'agente**: `<AGENT_DIR>/VERSION` uguale ad `AGENT_VERSIONE_ATTESA` (§16);
4. `settings_show.py`: legge i limiti dei documenti (`max_bytes`) e le estensioni audio,
   così caricamenti e agente usano gli stessi numeri.

`GET /salute` (senza firma, per il CMS): `200 {"ok": true}` se l'avvio è passato e l'ultima
verifica periodica (ogni 5 min: `VERSION` invariato) è buona, altrimenti `503 {"ok": false}`.
Nessun dettaglio (versioni, percorsi) senza autenticazione.

## 9. Lavori lunghi (`app/lavori/`)

- `asyncio.Queue` con **un** worker nel processo uvicorn unico (`--workers 1`, nessun
  `--reload` in produzione). Lavoro = `{id, azione, run, utente, stato, accodato_il,
  iniziato_il, esito}`; un lavoro per run alla volta (un secondo sulla stessa run → 409
  `RunBusy` del controller, senza aspettare l'agente). Coda limitata (`CODA_MAX`, 20) → 503.
- Avanzamento: per `produci` il controller legge `output/<run>/_eventi.jsonl` (aperto senza
  seguire link, solo righe complete) e lo inoltra in SSE; per stesura e revisione, che non
  hanno eventi, lo stato viene dal lavoro e da `script_show.in_corso`. Lo SSE funziona anche
  dopo un riavvio o da un altro browser, perché legge il file. Heartbeat ogni 15 s (per il
  proxy).
- Interruzione: **un solo SIGTERM** per lavoro, mai un secondo (un'altra richiesta risponde
  "interruzione già richiesta"). Allo spegnimento del servizio: un SIGTERM al lavoro in
  corso e attesa (systemd `TimeoutStopSec` lungo); nessun SIGKILL dal controller mentre
  l'ultimo evento è `fase_iniziata: preparazione_voci`.
- Esito del lavoro: stesso formato del §3 (gettone compreso per `ConsentRequired`,
  `CloneOutcomeUnknown`, `MusicChanged`), consegnato con l'evento SSE `lavoro` e in
  `GET /api/lavori`.

## 10. File (`app/file/`)

**Caricamenti** (A2: documenti; A5: voci e brani). Corpo grezzo (`application/octet-stream`)
con il nome nell'header `X-LIL-Nome-File`, codificato come `X-LIL-Nome` (UTF-8 percent-encoded): così la dimensione si conta **in streaming** prima di scrivere
qualunque byte su disco (con multipart Starlette scriverebbe prima tutto in un temporaneo).
Regole del contratto: nome ridotto (NFC, niente `/ \ ..`, controllo, `.`/`-` iniziali, ≤ 150),
estensione in elenco (documenti: `.pdf .docx .txt .md .markdown .rst .text`; audio: quelle di
`settings_show`; mai `.json .lock .tmp`), firma dei primi byte (`%PDF`, `PK`, testo UTF-8
valido per i testuali; `RIFF…WAVE`, `ID3`/frame MP3, `ftyp`, `fLaC`, `OggS`, EBML per
`.webm`), `Content-Length` e conteggio in streaming contro il limite, temporaneo `.<nome>.tmp`
nella stessa cartella con `O_EXCL|O_NOFOLLOW`, `fsync`, `rename`. Collisione di nome
(confronto dei comandi: senza estensione, minuscole, senza accenti, `_`/`-` come spazio) →
409 `FileEsistente` con gettone; rimandando il file con l'header `X-LIL-Gettone` si sostituisce e si toglie il
vecchio (anche con un'estensione diversa). Mai durante un lavoro della run che lo usa.

**Download**: solo nomi che l'agente elenca (`episode_info` per gli episodi, `documents_list`
per i documenti), risolti dentro `output/<run>` o `documenti/` con `os.open(O_NOFOLLOW)` e
controllo che il file reale sia lì dentro; `Range` (un intervallo, 206/416), `Content-Type`
da estensione, `Content-Disposition` con nome sicuro, `X-Content-Type-Options: nosniff`.

## 16. Decisioni (confermate il 2026-10-09)

1. **Versione dell'agente**: file `podcast-agent/VERSION` (`1.0-web`), unica modifica
   autorizzata all'agente (commit "agente: file VERSION", tag `v1.0.1-web`). Il controller lo
   legge all'avvio e non parte se è diverso da `AGENT_VERSIONE_ATTESA`.
2. **Firma**: nome e query firmati, corpo no.
3. **Errori dell'adattatore** (`InvalidArguments`, `NotAllowedInWebMode`, `ByRequired`,
   `InternalError`): 500, sempre nel log del controller con il dettaglio.
4. **Dipendenze**: tutte fissate in `requirements.lock`; niente `python-multipart` se non
   serve.
5. **Permessi** come al §5. In `DEPLOY.md`: il CMS invia questi nomi di ruolo, il dev li
   associa ai gruppi aziendali.
6. **Proxy del CMS** (in `DEPLOY.md`): caricamenti come corpo grezzo inoltrati intatti fino
   ad almeno 20 MB, nome del file nell'header `X-LIL-Nome-File` codificato come `X-LIL-Nome`;
   SSE senza buffering, polling come ripiego.
